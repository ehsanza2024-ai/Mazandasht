# سامانه اکسل مازندشت — Mazandasht Excel System

سیستم حسابداری، حسابرسی و تحلیل حساب‌های بانکی **«مازندشت»** (سورتینگ و بسته‌بندی مرکبات — باغدشت، بخش مرکزی، شهرستان قائم‌شهر، استان مازندران)

ساخته‌شده با فرمول‌های **کلاسیک و سازگار با Excel 2013** (بدون توابع جدید ۲۰۱۶ به بعد)، نام فایل‌ها/شیت‌ها/فرمول‌ها انگلیسی، محتوای کاربری فارسی و راست‌به‌چپ.

---

## ۱) فایل‌های سامانه

| فایل | نقش |
|---|---|
| `Mazandasht_INFO.xlsx` | **فایل مادر** — همه تعریف‌ها: بانک‌ها، مشتریان، **فروشندگان**، تأمین‌کنندگان (حجره‌داران میدان بار و…)، سایر حساب‌ها، کارکنان، انواع طرف حساب، انواع تراکنش، محصولات خرید/فروش، سبدها، انبارها، مشخصات شرکت |
| `Mazandasht_Transactions.xlsx` | **فایل واریز/برداشت** — تراکنش‌های همه حساب‌های بانکی در یک شیت ورودی (Entry)، صورت‌حساب خودکار ۱۰ بانک (Bank1…Bank10)، خلاصه و تحلیل (Summary) |
| `Mazandasht_Sales.xlsx` | **فایل فروش** — فاکتورهای فروش با ۱۵ ردیف محصول + کنترل ۱٪ اختلاف وزن + **صورت‌حساب خودکار هر فروشنده (شیت‌های SL001…SL100)** |

> همه فایل‌ها باید همیشه **در یک پوشه** باشند (لینک بین‌شان نسبی است).

## ۲) شیت‌های فایل تراکنش‌ها

- **Entry** — ورود داده: تاریخ، ساعت، بانک (کشویی)، کد طرف حساب (با نامِ خودکار)، نوع طرف حساب (کشویی)، نوع تراکنش (کشویی)، مبلغ واریز/برداشت، موجودی واقعی بانک + کنترل خودکار مغایرت (√ منطبق / × مغایر / — بدون کنترل / ؟ غیرقابل محاسبه). ردیف‌ها **نیازی به مرتب بودن ندارند**.
- **Bank1 … Bank10** — صورت‌حساب هر بانک: مرتب‌شده به تاریخ و ساعت، مانده سیستم جاری، مقایسه با موجودی دستی، تشخیص ردیف تکراری، کارت‌های خلاصه (جمع واریز/برداشت، مانده نهایی، وضعیت مغایرت، آخرین تاریخ…)، مشخصات رسمی بانک (شعبه/شماره حساب/شبا — ورود دستی) و عنوان خودکار از فایل مادر.
- **Summary** — خلاصه ۱۰ بانک + جمع کل، تحلیل ماهانه با انتخاب سال، دو نمودار، نشانگر سلامت اتصال به فایل مادر.
- **Sync** — آینه فایل INFO با لینک واقعی بین‌فایلی (منبع کشوها و کدها).
- **Calc** — موتور محاسبات: نرمال‌سازی تاریخ/ساعت (1405/7/9 و 14050710 و 9:5 همه پذیرفته و استاندارد می‌شوند)، کلید مرتب‌سازی و رتبه‌بندی.
- **Help** — راهنمای کامل فارسی.

## ۲ب) شیت‌های فایل فروش (Mazandasht_Sales.xlsx)

- **SL001 … SL100 — صورت‌حساب خودکار هر فروشنده:**
  - سربرگ: کد سازمانی، نام، نوع مشتری، تلفن/همراه و نشانی (خودکار از INFO) + «مانده اولیه» دستی
  - کارت‌های تجمیع: جمع بدهکار، جمع بستانکار، مانده نهایی، **ماهیت حساب (▲ بدهکار / ▼ بستانکار / = تسویه)**، تعداد فاکتور/پرداخت، جمع وزن ارسالی/فروش، آخرین تراکنش
  - دفتر تراکنش (۲۰۰۰ ردیف، خودکار و مرتب به تاریخ/ساعت): تاریخ | نوع عملیات (فروش/پرداخت بانکی) | مرجع | توضیحات | **وزن ارسالی و فروش (فقط ردیف‌های فروش)** | **بدهکار** (مبلغ صافی فروش) | **بستانکار** (واریز بانکی) | مانده جاری
  - منبع پرداخت‌ها: فایل واریز/برداشت — واریز هر فروشنده را آنجا با کد `SLxxx` ثبت کنید تا اینجا به‌صورت بستانکار بیاید
- **Ledger** — موتور ترکیب و رتبه‌بندی رویدادها (فروش + پرداخت) برای شیت‌های SLxxx
- **Entry** — هر ردیف = یک فاکتور فروش (یک ماشین‌بار):
  - **محدوده چاپ (A تا H):** ردیف | تاریخ | شماره فاکتور (عدد آزاد) | کد فروشنده (کشویی؛ کد غلط = خطای Stop) | نام فروشنده (خودکار) | وزن ارسالی | وزن فروش | مبلغ صافی
  - **ناحیه فقط-اکسل (خارج از چاپ):** اختلاف وزن + تیک/ضربدر کنترل سقف ۱٪ وزن ارسالی، جمع وزن محصولات و اختلاف آن با وزن ارسالی، سپس **۱۵ ردیف محصول** — هر کدام ۵ ستون: محصول (کشویی) | نوع سبد (خودکار) | نوع مرکبات (خودکار) | تعداد سبد | وزن. این ستون‌ها با دکمه +/− جمع می‌شوند.
- **Sync / Calc / Help** — آینه فایل مادر، موتور محاسبات (نرمال‌سازی تاریخ، کد فروشنده، آمار اقلام) و راهنما.

فروشندگان در INFO ← شیت **Sellers** (کد SL001…، نام صاحب حساب، **نوع مشتری** کشویی از PartyTypes: حجره‌دار، صادراتی، واسطه، نقدی و… قابل گسترش). هر محصول فروش در INFO ← **Products_Sell** دارای «نوع سبد» و «دسته (نوع مرکبات)» است که با انتخاب محصول خودکار در Entry نوشته می‌شود.

## ۳) شروع سریع

1. هر دو فایل را در یک پوشه بگذارید و `Mazandasht_Transactions.xlsx` را باز کنید.
2. هنگام باز شدن، پیام Update Links را با **Update** جواب بدهید (یا Data ← Edit Links ← Update Values).
3. در شیت **Entry** تراکنش‌ها را زیر هم ثبت کنید (۶ ردیف نمونه از قبل وجود دارد — پس از آشنایی محتوایشان را پاک کنید).
4. نتیجه را در برگه بانک مربوطه و در **Summary** ببینید.

## ۴) قواعد کدگذاری (در INFO تعریف می‌شود)

| موضوع | قالب کد |
|---|---|
| بانک‌ها | `BANK01` … `BANK10` (کد ثابت، عنوان آزاد) |
| مشتریان | `C001` … |
| فروشندگان (خریداران-بازفروش) | `SL001` … |
| تأمین‌کنندگان (حجره‌دار، باغ‌دار، عامل) | `S001` … |
| سایر حساب‌ها (کارمزد، مالیات، صندوق…) | `X001` … |
| کارکنان / فروشندگان | `E001` … |
| انواع طرف حساب | `PT01` … |
| انواع تراکنش | `T01` … |
| محصولات خرید / فروش | `PB01` / `PS01` … |
| سبدها / انبارها | `BK01` / `W01` … |

**قواعد طلایی:** کدها را تغییر ندهید (سیستم با کد کار می‌کند)؛ برای حذف، محتوای سلول را پاک کنید نه خود ردیف؛ تاریخ با ارقام لاتین `1405/07/10` یا `14050710`؛ ساعت `09:30` یا `9:30`؛ در هر ردیف فقط واریز *یا* برداشت.

## ۵) معماری فنی (برای توسعه‌های آینده)

```
Mazandasht_INFO.xlsx (مادر)
        │  external link ([1]Sheet!Ref) + کش مقدارها
        ▼
   Sync (آینه) ──► کشوهای Entry (ListBanks / ListPartyTypes / ListTxnTypes با OFFSET داینامیک)
        │
        ▼
   Calc (نرمال‌سازی + کلید مرتب‌سازی YYYYMMDDhhmm|ردیف + رتبه COUNTIFS)
        │
        ▼
   Bank1..10 (MATCH روی کلید رتبه ← INDEX هر ستون) + Summary (SUMIFS/COUNTIFS)

Mazandasht_Sales.xlsx (فروش)
   Sync ── لینک [1]: INFO (کدها/عناوین) + لینک [2]: Transactions (پرداخت‌های SLxxx)
        ▼
   Calc (فاکتورها) + Ledger (ترکیب فاکتور+پرداخت، کلید YYYYMMDDhhmm|نوع|ردیف، رتبه COUNTIFS دوبلوکی)
        ▼
   SL001..SL100 (MATCH رتبه ← INDEX؛ مانده تجمعی؛ ماهیت ▲/▼/=)
```

**نکته کلیدی:** کلیدهای مرتب‌سازی همیشه یک جداکننده غیرعددی (`|`) دارند تا اکسل در COUNTIF آن‌ها را عدد فرض نکند و مقایسه متنی دقیق انجام شود.

- **مرتب‌سازی بدون آرایه‌فرمول:** کلید متنی ارقامی (برای هر بانک یکتا) + `COUNTIFS` برای رتبه + `MATCH/INDEX` برای کشیدن ردیف مرتب‌شده — کاملاً سازگار با 2013 و سریع.
- **کنترل مغایرت:** مانده سیستم (مانده اولیه از INFO + Σواریز − Σبرداشت تا آن لحظه) در برابر موجودی دستی شما؛ نمایش فقط یک علامت رنگی خودکار.
- **تشخیص تکراری:** تطبیق تاریخ+ساعت+بانک+طرف+مبالغ.
- ظرفیت فعلی: Entry = ۲۰۰۰ ردیف، هر بانک = ۵۰۰ ردیف، هر فروشنده = ۲۰۰۰ ردیف (با کپی فرمول ردیف آخر، قابل افزایش — هشدار پرشدن ظرفیت خودکار نمایش داده می‌شود).

## ۶) بازتولید و تست

```bash
python3 tools/build_mazandasht.py --all          # ساخت دوباره هر دو فایل
python3 tools/build_mazandasht.py --qa           # بیلد کوچک آزمایشی (لینک داخلی)
python3 tools/build_mazandasht.py --qa --external # بیلد کوچک با لینک واقعی
```

منطق فرمول‌ها با موتور محاسباتی تست شده است (نرمال‌سازی تاریخ، رتبه‌بندی و مرتب‌سازی، مانده جاری، مغایرت، تکراری، جمع‌های Summary و تحلیل ماهانه؛ در فایل فروش: نام فروشنده/محصول از کد یا برچسب، سبد و مرکبات خودکار، کنترل دقیق ۱٪ شامل مرز، جمع ۱۵ ردیف محصول، کدهای نامعتبر، و **صورت‌حساب کامل فروشندگان: ترکیب فاکتور+پرداخت، ترتیب تاریخ، مانده و ماهیت ▲/▼/=، تسویه کامل SL002 نمونه**).

## ۷) نقشه راه (فایل‌های بعدی روی همین کدها)

- فایل‌های تحلیلی و حسابرسی فروش: فروش به تفکیک فروشنده/محصول/سبد، مطابقت آماری وزن‌ها (از Calc فایل فروش با نام‌های `SC…`)
- فایل خرید و انبار (محصولات `PB/PS`، سبدها `BK`، انبارها `W`)
- صورت‌حساب مشتری/تأمین‌کننده (بدهی/طلب از کدهای `C/S/X/SL`)
- تحلیل‌های تخصصی مرکبات (درجه‌بندی، ضایعات، بازده خط سورتینگ)
